# Resume Feature Implementation

**Date:** 2026-02-11
**Feature:** Session Resume (`arkadian --resume`)

## Summary

Implemented complete session resume functionality that allows users to continue interrupted or incomplete orchestrator sessions from their last completed phase. Handles the session rename issue by searching `workflow.yaml` files for original UUIDs.

## Changes

### 1. CLI Script (`scripts/arkadian`)

**Added:**
- `--resume <session_id>` flag parsing
- `SESSIONS_DIR` variable for session directory management
- `RESUME_SESSION` variable to track resume mode
- `RESUME_PROMPT` construction for orchestrator instructions

**Session Detection Logic:**
1. Try direct directory match (`sessions/{id}`)
2. Try nested directory search (`sessions/*/`{id}`)
3. **NEW:** Search all `workflow.yaml` files for matching `workflow_id` (handles renamed sessions)

**Environment Variables Exported:**
- `ARKADIAN_RESUME_SESSION` - Session ID to resume
- `ARKADIAN_RESUME_SESSION_DIR` - Full path to session directory

**User Feedback:**
Shows clear session analysis before launching orchestrator:
```
Resuming session: 2026-02-11-add-getroundmetrics-grpc-endpoint-arkd-adminservic
  Directory: /Users/.../sessions/arkd/2026-02-11-...

Session state analysis:
  ✅ explore: COMPLETE (ark-guru)
  ⏸️  implement: IN PROGRESS or FAILED (no _result.json)

Next phase to execute: S3.yaml
```

### 2. Orchestrator Instructions (`ORCHESTRATOR.md`)

**Added new section: "Resume Mode Detection"** (inserted before "Mandatory Approval Protocol")

**Content:**
- Environment variable detection (`ARKADIAN_RESUME_SESSION`)
- Step 0: Analyze Session State
  - Read `workflow.yaml` for phases
  - Check `artifacts/{phase}/_result.json` for completion
  - Identify next pending phase
- Step 1: Report Resume State to user
- Step 2: After approval, invoke agent
- Step 3: Continue normal workflow

**Critical Rules:**
- NEVER re-run completed phases
- NEVER skip execution spec approval
- DO use existing artifacts from previous phases
- DO respect workflow.yaml structure

### 3. Status Command Enhancement

**Updated `cmd_status_detail()` function** to support UUID lookup:
- After trying active state file, log file, and manifest
- **NEW:** Search `workflow.yaml` files for matching UUID
- Display phase completion status from `_result.json` files
- Show both artifacts/ phases and specs/ planning phases

**Example:**
```bash
arkadian status 3191f042-a27d-4a6e-b6a8-f2fe0f41bc9a
# Works even though directory was renamed!
```

## Problem Solved: Session Rename Issue

**Original Issue:**
User asked: "if session breaks it will rename folder name from session id to other name which is title generated by ai, how would we resume it after we change folder name"

**Root Cause:**
- During session: `sessions/3191f042-a27d-4a6e-b6a8-f2fe0f41bc9a/`
- After session ends: `sessions/arkd/2026-02-11-add-getroundmetrics-grpc-endpoint-arkd-adminservic/`
- User loses the UUID, can't resume with original ID

**Solution Implemented:**
1. **Preserve UUID in workflow.yaml:**
   ```yaml
   workflow_id: 3191f042-a27d-4a6e-b6a8-f2fe0f41bc9a
   ```

2. **Search mechanism:**
   ```bash
   # If directory not found by name, search workflow.yaml files:
   for workflow in $(find sessions/ -name "workflow.yaml"); do
       workflow_id=$(grep "^workflow_id:" "$workflow")
       if [[ "$workflow_id" == "$RESUME_SESSION"* ]]; then
           # Found it! Use this directory
       fi
   done
   ```

3. **User experience:**
   Both of these now work:
   ```bash
   # Original UUID (from logs or early in session)
   arkadian --resume 3191f042-a27d-4a6e-b6a8-f2fe0f41bc9a

   # Renamed directory (from sessions/ folder)
   arkadian --resume 2026-02-11-add-getroundmetrics-grpc-endpoint-arkd-adminservic
   ```
