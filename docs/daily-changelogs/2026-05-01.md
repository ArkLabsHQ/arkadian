## Highlights for your stack

### arkd (1 commit)
- **Breaking client-lib wallet interface rewrite**: `WalletService` swaps address methods (`GetAddresses`/`NewAddress`/`NewAddresses`) for key-ref methods (`NewKey`/`GetKey`/`ListKeys`/`NextIndex`); `SignTransaction(ctx, tx, keys map[string]string)` no longer takes an explorer; `Create` now takes `chaincfg.Params`; `NewVtxoTreeSigner` drops the derivation-path arg (`9246f043` by Pietralberto Mazza, co-authored by you)
- **Breaking `ArkClient` surface**: `InitWithWallet` removed entirely — `NewArkClient` must now use `WithWallet` option; `InitArgs.WalletType` removed; `GetAddresses` return type changed (offchain/boarding/redemption now `[]types.Address` instead of `[]string`); `clientStore` dropped (`9246f043`)
- **API additions (variadic opts)**: `SignTransaction`, `RegisterIntent`, `DeleteIntent`, `FinalizePendingTxs`, `CompleteUnroll`, `OnboardAgainAllExpiredBoardings`, `WithdrawFromAllExpiredBoardings` all gained `opts ...SignOption`/`...UnrollOption` (`9246f043`)
- **New `WithKeys(map[string]string) SignOption`**: cross-family option usable in Send/Batch/Unroll calls; lets callers pass `keyId-by-prevout-script` to drive per-input signing (`9246f043`)
- **Singlekey wallet trimmed ~345→? lines**: `bitcoin_wallet.go` lost ~half its body as address bookkeeping moved out (`9246f043`)

### Cross-cutting
- **arkd → go-sdk**: this is a hard break for any go-sdk-derived client. Downstream callers must (1) drop `InitWithWallet`/`WalletType`, switch to `NewArkClient(WithWallet(...))`; (2) update `GetAddresses` consumers for the new typed return; (3) thread `WithKeys` (or accept default) into `SignTransaction`/`RegisterIntent`/`Settle`/`Unroll`; (4) re-implement any custom `WalletService` against the new key-ref API and the explorer-free `SignTransaction`.
- **fulmine / introspector impact**: if either embeds a custom `WalletService` or calls `InitWithWallet`, expect compile breaks on the next arkd bump — plan a coordinated update.
