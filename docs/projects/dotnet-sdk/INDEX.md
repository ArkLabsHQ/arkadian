# NArk (.NET Ark SDK) -- Project Index

**dotnet-sdk** is a .NET SDK (C#) for building Ark protocol wallets and applications. It provides a complete client-side implementation including VTXO management, batch session participation (MuSig2 tree signing), intent-based transaction construction, coin selection, sweeping, on-chain operations, and Boltz atomic swap integration. Published as NuGet packages.

## Key Concepts

- **ArkContract** — Abstract Taproot contract: ArkPaymentContract, ArkNoteContract, HashLockedArkPaymentContract, VHTLCContract
- **ArkIntent** — Signed transaction intent registered with arkd for batch inclusion
- **ArkVtxo** — Virtual Transaction Output with expiry, sweep, and spend tracking
- **ArkCoin** — VTXO paired with its contract for spending
- **ArkVtxo** — Domain VTXO record. Exposes `IsUnconfirmedOnchain()` (PR #101) which reads the shared `ArkVtxo.ConfirmedMetadataKey = "Confirmed"` metadata flag (populated today only by `BoardingUtxoSyncService` from the explorer's confirmation status; off-chain tree VTXOs that lack the key return `false`). Confirmation-centric rather than boarding-specific: if arkd-reported unrolled VTXOs later carry the same flag, every consumer generalises for free. `SpendingService.GetAvailableCoins` filters these out — arkd's `validateBoardingInput` rejects unconfirmed boarding inputs at settle time, so any spend built from one is doomed. The sample wallet surfaces the state as a **PENDING** pill on `Vtxos.razor`
- **ArkPayment / ArkPaymentRequest** — Outbound payment + inbound payment-request domain models tracked by `PaymentTrackingService` (now an `IHostedService`; supports asset tracking via `ArkPayment.Assets` / `ArkPaymentRequest.ExpectedAsset` + `ReceivedAssets`; explicit `Cancelled` status distinct from `Failed`)
- **ArkBip21** — Builder + parser for BIP21 URIs covering Ark addresses, BOLT11 invoices, LNURL, and Bitcoin addresses into a unified `Bip21PaymentInfo` with `PreferredMethod` routing (`ArkSend` / `SubmarineSwap` / `ChainSwap`); `Parse` (lenient) and `ParseStrict` modes. `Build()` requires at least one destination from `{arkAddress, onchainAddress, lightning}` and emits the empty-address form (`bitcoin:?lightning=…` or `bitcoin:?asset=…`) when only the query side is populated — PR #109 widened the precondition so receive screens that toggle Ark / on-chain chips off while keeping Lightning don't have to switch QR schemes. `assetId` is a constraint on what to send (not a destination) and cannot stand alone
- **LnurlHelper** — `NArk.Core.Payments.LnurlHelper` (lifted into the SDK from the WASM sample in PR #106). Client-side LNURL-pay decoder + Lightning-address resolver: `IsLnurl` (recognises `lnurl1…` bech32 + `lightning:` scheme + Lightning Addresses, rejects bare on-chain / leading `@`), `DecodeLnurl` (bech32 → URI), `ResolveAsync(input, ct)` (LUD-06 / LUD-16 → `LnurlPayParams` { callback, minSendable / maxSendable, metadata, … }), `FetchInvoiceAsync(callback, amountSats, ct)` (millisat conversion, `?`/`&` separator handling, `error` field surfaced as exception). No new dependencies — uses NBitcoin's bech32 encoder + built-in `System.Net.Http.Json`. Public API matches the WASM sample's prior version; `CancellationToken` parameters added throughout for SDK-style consistency. The Blazor sample wallet now consumes the SDK type via `using NArk.Core.Payments;` so downstream wallet hosts no longer copy-paste it
- **ArkWalletInfo** — Wallet record. `Secret` is **nullable** (PR #107): `null`/empty means the wallet has no local key — watch-only or remote-signed, distinguished at runtime by `IWalletProvider.GetSignerAsync`. `WalletType` stays minimal (`SingleKey | HD`) — observability and remote-signing are *orthogonal axes* answered by the signer-provider, not flags on the wallet record. `WalletFactory.CreateWatchOnlyWallet(accountDescriptor, …)` infers `WalletType` from the descriptor's wildcard at creation time
- **IArkadeWalletSigner / CompositeArkadeWalletSigner** — Public signer contract; the SDK's only `IArkadeWalletSigner` is `CompositeArkadeWalletSigner`, built from one or more `IDescriptorSigningSource`s (PR #114). The composite dispatches each call (`GetPubKey`, `Sign`, `GenerateNonces`, `SignMusig`) to the first source that claims the descriptor via `CanProvideAsync`. The three previous concrete signers (`HierarchicalDeterministicWalletSigner`, `NSecWalletSigner`, `RemoteArkadeWalletSigner`) are deleted; existing call sites compile unchanged because the public interface didn't move
- **IDescriptorSigningSource** — Operation-level signing-source contract (`CanProvideAsync(descriptor)` + `GetPubKey` / `Sign` / `GenerateNonces` / `SignMusig`). Never exposes `ECPrivKey` — that's the point: a remote source can implement it honestly without round-tripping secret material over the wire. Three sources ship: `Bip39SigningSource` (claims by master fingerprint match on the descriptor's origin — replaces `HierarchicalDeterministicWalletSigner`), `NsecSigningSource` (claims by x-only pubkey match on `tr()` descriptors — `NsecSigningSource.FromNsec` mirrors the old `NSecWalletSigner.FromNsec` static), `RemoteTransportSigningSource` (claims via `IRemoteSignerTransport.KnowsWalletAsync`; passthrough proxy — replaces `RemoteArkadeWalletSigner`). Each local source keeps its own per-session `ConcurrentDictionary<string, MusigPrivNonce>` nonce store
- **IRemoteSignerTransport** — Remote-signer transport contract (PR #107). Mirrors `IArkadeWalletSigner` with an extra `walletId` parameter on every method so a single transport instance can serve multiple wallets (server-side signing service, hardware bridge, browser extension shared across tabs). `KnowsWalletAsync(walletId, ct)` is the wallet-grained probe `DefaultWalletProvider` uses to decide whether to wire a `RemoteTransportSigningSource` for a null-Secret wallet (returns `true` → remote-signed; `false` or no transport registered → watch-only). MuSig2 surface (PR #113): `GenerateNoncesAsync` returns `MusigPubNonce` only (secret half stays inside the signer); `SignMusigAsync` drops the `MusigPrivNonce` parameter and looks the secret up by `(walletId, sessionId)`. `<remarks>` block notes long-lived transports need an eviction policy (TTL or bounded count) for abandoned nonces. **PR #116** `SignAsync`'s `<remarks>` now also requires implementations **SHOULD** sign with `aux_rand` set to null (or all-zero) so the signature is deterministic per `(key, hash)`: `SwapsManagementService.DerivePreimageAsync` depends on this for the swap-preimage recovery scheme — same descriptor + same wallet must produce the same signature, otherwise a restored wallet that rediscovers an outstanding swap re-derives a different preimage and fails to claim the VHTLC. Transports that randomise `aux_rand` (e.g. hardware-signer side-channel hardening) still execute swaps fine but lose the post-restore claim story
- **DefaultWalletProvider** — `GetSignerAsync` builds a `CompositeArkadeWalletSigner` per wallet by composition: (1) **cache check first** (PR #114 — short-circuits before any source construction, avoids per-VTXO master-fingerprint derivation + `KnowsWalletAsync` round-trips on the hot batch path); on cache miss: (2) add the matching local source if `Wallet.Secret` is set (`Bip39SigningSource` for HD, `NsecSigningSource` for SingleKey); (3) probe the registered `IRemoteSignerTransport.KnowsWalletAsync` (if any) and add `RemoteTransportSigningSource` when it claims the wallet. Local sources get first refusal; remote is fallback. Returns `null` for true watch-only (Secret null + no transport claim). Signer cache key is `wallet.Id` alone (PR #114 simplified from `(walletId + secret hash + transport)` — re-import is handled out-of-band by host restart). `IRemoteSignerTransport` is an optional constructor parameter
- **BatchSession / BatchManagementService** — Participates in arkd batch rounds: nonce exchange, tree signing (MuSig2), forfeit tx signing. **PR #118** closes a stream-topic subscription race: an intent that reached `WaitingForBatch` during the gRPC stream-connect window (before `_streamId` was set) had its `UpdateTopicsAsync` call silently skipped by the null-stream guard with no retry, leaving it un-subscribed — it never received `BatchStartedEvent`, never participated in signing, and arkd kept re-proposing it every batch round forever (a permanent settle stall). When `StreamStartedEvent` now sets `_streamId`, the handler reconciles by re-subscribing every active intent's topics via `GetAllTopics()`; `UpdateStreamTopics` add is idempotent (server-side set union), so re-adding already-subscribed topics is a harmless no-op — the reconcile only ever adds the topics stranded during the connect window. Diagnosed via an intermittent `CanStartUnilateralExitForSettledVtxo` E2E timeout where the test was stuck waiting on `BatchSucceeded`
- **TreeSignerSession** — MuSig2 nonce and partial signature session for VTXO trees. `_myNonces` collapsed to `Dictionary<uint256, MusigPubNonce>` (PR #113) — the secret half no longer round-trips through the batch coordinator. Passes each tree-node txid as the `sessionId` argument on `GenerateNonces` / `SignMusig` so the signer can disambiguate nonces across sibling tree txs that share cosigner set + tweak (their `MusigContext.AggregatePubKey` is identical even when sighashes differ)
- **SpendingService** — Builds and submits Ark transactions with automatic coin selection, change handling, server-driven amount bounds + OP_RETURN limits. **PR #145/#146** replaced the fixed `ArkTransactionLimits.MaxVtxosPerArkTransaction` input cap with a per-input **weight budget**: it computes `inputWeightBudget = serverInfo.MaxTxWeight − ArkTxWeightEstimator.BaseTxWu − outputsWu` and passes it as the new `maxInputWeightWu` argument to `ICoinSelector`. `outputsWu` reserves room for the user outputs, one potential BTC change output, the always-present P2A anchor (`P2AOutputWu`), **and** — when assets are involved — the asset-packet OP_RETURN (`EstimateAssetPacketWu`, which models one input per required asset plus the explicit output asset entries); omitting the latter two over-budgets the inputs and risks arkd's `TX_TOO_LARGE` rejection
- **ArkTxWeightEstimator** — `static class` in `NArk.Core/Fees/` (PR #145) that computes Bitcoin weight units (WU) for Arkade VTXO inputs and outputs, matching the Arkade server's `baseSize×3 + totalSize` formula. `GetInputWeightUnits(ArkCoin)` measures a VTXO spent via its tapscript (script-path) path — control-block + script length + one 64-byte signature per `OP_CHECKSIG`/`OP_CHECKSIGVERIFY` opcode (mirroring arkd's `MultisigClosure.Witness`) + any spending-condition witness items. `GetOutputWeightUnits(TxOut)` measures an arbitrary output from its serialized size (used for the asset-packet OP_RETURN). Typed constants `BaseTxWu` (42), `P2TrOutputWu` (172), `P2AOutputWu` (52). Deliberately hand-rolled instead of `PSBT.TryGetVirtualSize` because the codebase stores taproot script-path metadata in raw PSBT `Unknown` fields, which NBitcoin doesn't parse back — it would silently fall back to the much-smaller key-path estimate (~69 vs ~102 vbytes for a standard `ArkPaymentContract` input). Pinned by `NArk.Tests/ArkTxWeightEstimatorTests.cs`. Replaces the deleted `ArkTransactionLimits.cs` (the flat 50-VTXO-per-tx cap)
- **ICoinSelector / DefaultCoinSelector** — Coin-selection contract. **PR #145** changed both `SelectCoins` overloads' final parameter from `int? maxInputs` to `long? maxInputWeightWu` (a weight-unit budget rather than an input count). `DefaultCoinSelector` (still the DI default, registered by `AddArkCoreServices`) accumulates `ArkTxWeightEstimator.GetInputWeightUnits(coin)` as it greedily adds inputs and stops / throws `TooManyInputsException` once `usedWu + coinWu > cap`; all four selection strategies (greedy, push-change-above-dust, subset-optimise, max-change-fallback) now respect the weight budget instead of an input count, and the asset-aware overload threads the remaining budget (`total − usedWu`) into the BTC fill
- **EARSCoinSelector** — Expiry-Aware Randomized Coin Selector (PR #124), an **alternative** `ICoinSelector` impl under `NArk.Core/CoinSelector/EARS/` (the default registration stays `DefaultCoinSelector`; swap it in via DI). Groups candidate VTXOs into expiry **buckets** (coins expiring within `CoinSelectionPolicy.ExpiryWindowBlocks`, ~144 blocks / 24h, of the earliest in the bucket; no-expiry coins go last) and runs four strategies via `CoinSelectionEngine` — `ExpiryFirstStrategy`, `RgliStrategy`, `SingleRandomDrawStrategy`, `BranchAndBoundStrategy` — picking the result with lowest **waste** (`change + inputCount × CostPerInputSats`). Asset requirements are reserved first (expiry-aware, earliest-first), then BTC is filled from the remaining candidates and merged. `CoinCandidate` carries each coin's `ArkTxWeightEstimator.GetInputWeightUnits` weight; the same `maxInputWeightWu` budget surfaces a `TooManyInputsException` when funds are sufficient but too fragmented. Pinned by `NArk.Tests/EarsCoinSelectorTests.cs`
- **TooManyInputsException** — Thrown when a spend is fundable in total but the VTXOs are so fragmented their combined input weight would breach the server's `max_tx_weight` (arkd rejects with `TX_TOO_LARGE`). **PR #145** changed its constructor/property from `MaxInputs` (an int count) to `MaxInputWeightWu` (a `long` weight budget); the message advises consolidating VTXOs or sending a smaller amount
- **SimpleIntentScheduler** — Auto-consolidation intent scheduler. **PR #145** replaced the fixed `Chunk(ArkTransactionLimits.MaxVtxosPerArkTransaction)` batching with `ChunkByProofTxWeight(coins, serverInfo.MaxTxWeight)`: it packs VTXOs (value-descending) into chunks whose **proof-tx weight** stays under `max_tx_weight`, accounting for the fixed `BaseTxWu + P2TrOutputWu` overhead, the fact that `inputs[0]` counts twice in the proof tx (regular input + `toSpend` duplicate), and the asset-packet OP_RETURN that grows with each asset-bearing input. A single oversized coin still emits as its own chunk rather than looping. Pinned by `NArk.Tests/SimpleIntentSchedulerTests.cs`
- **VtxoSynchronizationService** — Keeps **one long-lived arkd `GetSubscription` stream** open and mutates the watched script set **in place** via `SubscribeForScriptsAsync` / `UnsubscribeForScriptsAsync` deltas — contracts coming and going no longer tear the stream down (PR #103). A supervisor loop owns the stream, reconnects on the same subscription id, recreates it if arkd reports it GC'd (TTL after a disconnect), and tears it down when the active set is empty. The 5 s safety-net poll **re-derives the active script set fresh from `IActiveScriptsProvider`s every tick** (PR #102) — a stale or missed `ActiveScriptsChanged` event can never hide a script from detection because the next tick re-derives, polls, and reconciles the subscription. `_lastViewOfScripts` was renamed to `_subscribedScripts` and demoted to pure stream-subscription bookkeeping. `GatherActiveScriptsAsync` isolates per-provider failures so one storage hiccup can't blank the set. Each stream push still enqueues a **single immediate poll** (PR #99's drop of the 750 ms / 3 s / 8 s retry fan-out stands). Persists a per-wallet `vtxo.lastFullPollAt` cursor (via `ArkWalletEntity.Metadata`) to bound cold-start catch-up; gated so a failed catch-up + successful routine poll cannot advance past the gap
- **ArkWalletEntity.Metadata** — Generic JSON-serialized `Dictionary<string,string>?` column for per-wallet bookkeeping (sync cursors, recovery state, etc.) — provider-agnostic (`jsonb` / `TEXT` / `nvarchar(max)`); written through `IWalletStorage.SetMetadataValue` (sparse-key, concurrent-writer-safe; `value=null` removes). The `Wallet` column itself is **nullable** since PR #107 — watch-only and remote-signed wallets have `Secret=null` so their EF Core row stores `NULL` in `Wallet`. The unique index carries `.HasFilter("\"Wallet\" IS NOT NULL")` so SQL Server doesn't reject multiple null rows (Postgres / SQLite already treat `NULL` as distinct under the unique index — the filter is harmless there and makes intent explicit)
- **SweeperService** — Monitors and redeems expired/swept VTXOs on-chain
- **PendingArkTransactionRecoveryService** — Reconciles Arkade off-chain txs stranded between `SubmitTx` (server locked inputs as in-flight) and `FinalizeTx` (crashed before sending). Runs on host startup via `ArkHostedLifecycle` (after VtxoSync) across every wallet; also exposes `FinalizePendingArkTransactionsAsync(walletId)` for on-demand per-wallet recovery. Builds BIP-322 ownership proofs anchored on each batch's first VTXO (including spent VTXOs for proof material), calls the new `GetPendingTxAsync` transport endpoint, signs the returned checkpoint PSBTs, and finalizes them. Per-tx failures raise `RecoveryFailed` (`PendingTxRecoveryFailureEventArgs`) without blocking the loop
- **SwapsManagementService** — Provider-agnostic router over `IEnumerable<ISwapProvider>`. Orchestrates submarine (Ark→Lightning), reverse (Lightning→Ark), and ARK<->BTC chain swaps; exposes `InspectSwapRecoveryAsync` / `ScanRecoverableSwapsAsync` for read-only recovery-state diagnostics across all four swap types. Existing public Initiate* / PayExisting* / Restore* methods remain as backward-compatible wrappers that delegate to the resolved `BoltzSwapProvider`. Stamps `BoltzClientOptions.ReferralId` (default `"arkade-dotnet-sdk"`) on every swap-create request. **PR #123** carves `RegisterArkToBtcChainSwapAsync(walletId, amountSats, btcDestination, ct)` out of `InitiateArkToBtcChainSwap` as an `internal` method: it talks to Boltz, imports the VHTLC contract via `IContractService.ImportContract` (the missing `ImportContract` call was a separate ARK→BTC bug), saves the swap row with the correct ScriptPubKey hex, and returns `(SwapId, VhtlcAddress, LockupAmount, TimeoutBlockHeight)` — but does **not** send the lockup transaction. `InitiateArkToBtcChainSwap` is now a thin wrapper that calls `RegisterArkToBtcChainSwapAsync` and then `SpendingService.Spend` to fund the VHTLC. The split lets E2E tests register a swap and mine past the timeout before funding to exercise the natural `swap.expired` path. **PR #116** adds the deterministic-preimage recovery scheme. Reverse and chain-swap preimages are derived from the wallet's signing material via `DerivePreimageAsync(walletId, descriptor, index, ct)` → `SHA256(BIP-340-Sign(key, SHA256(PreimageTag || xonly_pubkey || u32_le(index))))`, where `PreimageTag = "Arkade-Boltz-Preimage-v1"` is intentionally protocol+provider scoped (not SDK-scoped) so any sibling Arkade SDK can reproduce the same preimage from the same wallet material. `BuildPreimageMessage(descriptor, index)` is the pure formatter pinned by `PreimageDerivationTests` — anchored on the canonical x-only pubkey (`.Extract().XOnlyPubKey.ToBytes()`) **not** the descriptor's string form, so an HD signing descriptor and the bare receiver descriptor a restore reconstructs produce the same message. `InitiateReverseSwap` / `InitiateBtcToArkChainSwap` / `InitiateArkToBtcChainSwap` derive the preimage at `index: 0` before calling `BoltzSwapsService`; watch-only wallets (signer resolves to `null`) fall back to `RandomUtils.GetBytes(32)`. `RestoreSwaps`'s reverse-swap branch re-derives a candidate preimage with `index=0` for each Boltz-rediscovered swap, hashes it, and on match against `restored.PreimageHash` attaches the preimage hex to `SwapMetadata.Preimage` so the sweeper can claim the VHTLC; mismatch leaves it out (`EnrichReverseSwapPreimage` remains the manual fallback). Submarine swaps are excluded — Boltz controls that preimage
- **ISwapProvider** — Pluggable swap-provider interface (`ProviderId`, `DisplayName`, `SupportsRoute`, `GetAvailableRoutesAsync`, `StartAsync`/`StopAsync`, `GetLimitsAsync`, `GetQuoteAsync`, `SwapStatusChanged` event, default no-op `NotifyVtxoChanged`/`NotifySwapChanged` hooks). Capability discovery via `SwapRoute`/`SwapAsset`/`SwapNetwork`/`SwapQuote`/`SwapLimits` models lets the router pick a provider for a given route
- **BoltzSwapProvider** — Boltz-specific `ISwapProvider` implementation: WebSocket monitoring, status polling, cooperative refunds (submarine + ARK→BTC + BTC→ARK chain), MuSig2 claiming, chain-swap renegotiation on `transaction.lockupFailed`, 10-consecutive-404 unknown-to-provider safety net, single long-lived Boltz websocket with subscribe/unsubscribe ops keyed by swap id. **PR #141** added **unilateral refund fallbacks for when Boltz permanently refuses the cooperative co-sign**: (a) `UnilateralRefundBtcToArkChainSwap` spends the BTC HTLC output via its refund tapscript leaf once the CLTV `lockupDetails.TimeoutBlockHeight` is reached (Boltz supplies the timeout as a plain int — no script parsing; `TryCoopRefundBtcToArk` was renamed `TryRefundBtcToArk` to reflect it now covers both coop + unilateral paths); (b) `TryRefundWithoutReceiverAsync` submits the VHTLC spend via the `refundWithoutReceiver` tapscript (server + sender, absolute CLTV) as an **Arkade batch intent** once `VHTLCContract.RefundLocktime` elapses, returning funds inside Arkade without an on-chain exit — the batch/`JoinRound` path is required because the block-height CLTV closure is rejected by arkd's `SubmitTx` checkpoint endpoint (`blockTypeAllowed=false`) and only the batch path enforces the locktime via the forfeit tx's `nLockTime`. `CheckRefundWithoutReceiverIntentAsync` tracks the in-flight intent (stored under `SwapMetadata.RefundIntentTxId`) so a settled refund batch transitions the swap to `Refunded` rather than being clobbered as `Failed` when the now-spent lockup VTXO disappears. Needs an optional `IIntentGenerationService` (constructor-injected) and subscribes to `IIntentStorage.IntentChanged` (`OnRefundIntentChanged`) to trigger an immediate poll on batch settlement instead of waiting up to a minute for `RoutinePoll`. Renegotiation acceptance now also re-polls immediately so the claim fires in the same cycle. Cooperative-refund / claim BTC-tx fees switched from a flat 250-sat constant to `EstimateClaimRefundFeeAsync` (mempool-driven via `IBitcoinBlockchain.EstimateFeeRateAsync(confirmTarget: 2)` over a ~111-vByte 1-in-1-out key-path spend). **PR #123** split the monolithic class into four partials — `BoltzSwapProvider.cs` (state, websocket, status polling, classification dispatch), `BoltzSwapProvider.Lifecycle.cs` (`StartAsync` / `StopAsync` / `ShutdownAsync` / `DisposeAsync`), `BoltzSwapProvider.Claims.cs` (`TryClaimBtcForChainSwap` / `TrySignBoltzBtcClaim`), `BoltzSwapProvider.Refunds.cs` (`RequestSubmarineCoopRefund` / `TryCoopRefundArkToBtc` / `TryCoopRefundBtcToArk` / `TryRenegotiateChainSwap`) — and delegated routing to `BoltzRouteHelper` (`SupportsRoute` / `GetAvailableRoutesAsync` / `GetLimitsAsync` / `GetQuoteAsync`) and recovery-action selection to `BoltzOperationClassifier.Classify(swap, boltzStatus)` (returns a `BoltzSwapAction?`). `PollSwapState` is now a flat `switch (classifier.Classify(...))` over the action enum, so the previous nested-if recovery dispatch is gone
- **BoltzOperationClassifier** — `public static class` (`NArk.Swaps.Boltz`) that maps `(ArkSwap, boltzStatus)` to a `BoltzSwapAction?` (PR #123). Each predicate (`CanRenegotiateChainSwap` / `CanCoopRefundSubmarine` / `CanCoopRefundArkToBtc` / `CanCoopRefundBtcToArk` / `CanClaimChainSwap` / `ShouldSignChainSwap`) is also exposed as an individual `public static bool` for ad-hoc reuse and is the focal point of the new `NArk.Tests/BoltzOperationClassifierTests.cs`. `ValidateTypeAndStatus` rejects swaps whose status `IsSuccess()` (`Settled` or `Refunded`) so a terminal swap can never be reclassified for refund/claim. Returning `null` means "no action — leave the status as Boltz reports it (operational), or apply the terminal mapping from `BoltzSwapStatus.ToArkSwapStatus`"
- **BoltzRouteHelper** — `public static class` (PR #123) carrying the Boltz route catalog (`SwapRoute[] Routes` — submarine `ArkBtc → BtcLightning`, reverse `BtcLightning → ArkBtc`, chain `ArkBtc → BtcOnchain`, chain `BtcOnchain → ArkBtc`) plus `SupportsRoute`, `GetAvailableRoutesAsync`, `GetLimitsAsync(route, BoltzLimitsValidator, ct)`, `GetQuoteAsync(route, amount, BoltzLimitsValidator, ct)`. `BoltzSwapProvider`'s `ISwapProvider` route methods are now one-line forwards into this class
- **BoltzSwapAction** — `public enum` (PR #123) of mutually-exclusive recovery actions returned by `BoltzOperationClassifier.Classify`: `CanCoopRefundSubmarine`, `CanCoopRefundArkToBtc`, `CanCoopRefundBtcToArk`, `CanRenegotiateChain`, `CanClaimChain`, `ReadyToSignClaim`. `PollSwapState` switches on the action; `CanRenegotiateChain` falls back to the matching `CanCoopRefund{ArkToBtc,BtcToArk}` branch in-line when renegotiation fails — that decision lives in the provider, not the classifier, because it depends on Boltz's runtime quote response
- **BoltzSwapStatus** — `public static class` (PR #123) holding every Boltz lifecycle status string as a `const` (mirrors `https://api.docs.boltz.exchange/lifecycle.html`): common (`SwapCreated`, `SwapExpired`), on-chain lockup (`TransactionMempool` / `TransactionConfirmed` / `TransactionServerMempool` / `TransactionServerConfirmed` / `TransactionLockupFailed` / `TransactionFailed`), claim (`TransactionClaimPending` / `TransactionClaimed`), refund (`TransactionRefunded`), submarine invoice (`InvoiceSet` / `InvoicePending` / `InvoicePaid` / `InvoiceFailedToPay`), reverse invoice (`InvoiceSettled` / `InvoiceExpired`), reverse miner fee (`MinerFeePaid`). `ToArkSwapStatus(string)` maps **only** the genuinely terminal statuses — `InvoiceSettled` / `TransactionClaimed → Settled`, `TransactionRefunded → Refunded`, `InvoiceExpired` / `TransactionFailed → Failed` — and returns `null` for operational ones, so the caller is forced to route them through `BoltzOperationClassifier` for any side effect. This replaces a previous local enum + open-coded string comparisons inside `BoltzSwapProvider`
- **ArkSwap / ArkSwapType / ArkSwapStatus / ArkSwapWithContract** — PR #123 split each type into its own file under `NArk.Swaps/Models/`. `ArkSwap` is now a focused `record` (no nested enums); `ArkSwapType` covers `Submarine` / `ReverseSubmarine` / `ChainArkToBtc` / `ChainBtcToArk`; `ArkSwapStatus` adds an explicit `Unknown` value alongside `Pending` / `Settled` / `Failed` / `Refunded` so the codebase can distinguish a swap that has never been classified from one stuck mid-flight (the new `IsActive` extension treats `Pending` and `Unknown` identically — both keep polling); `ArkSwapWithContract(Swap, Contract)` pairs a swap with its `ArkContractEntity?` for the storage join. The new `SwapExtensions` static class (`NArk.Swaps.Extensions`) exposes `IsActive(ArkSwapStatus)`, `IsTerminalState(ArkSwapStatus)`, `IsSuccess(ArkSwapStatus)`, and `Get(ArkSwap, string)` (metadata accessor) so the cleanup pass could drop scattered status / metadata checks
- **SwapMetadata** — `public static class` (PR #123 moved the well-known metadata keys here so they're constants instead of string literals on every read/write site). Chain-swap keys: `Preimage`, `EphemeralKey`, `BoltzResponse`, `BtcAddress`, `CrossSigned`. **`RefundDestination`** is new — set the first time a cooperative refund derives a destination contract via `SwapExtensions.GetOrDeriveRefundDestinationAsync(swap, contractService, swapStorage, network, ct)` so subsequent poll retries reuse the same address instead of deriving a fresh contract each tick and leaking orphan `IContractStorage` rows. **`RefundIntentTxId`** (PR #141) records the intent txid of an in-flight `refundWithoutReceiver` batch so subsequent poll ticks query the intent state instead of re-generating it. Persistence-shim constants (`ProviderId`, `RouteSourceNetwork`, `RouteSourceAssetId`, `RouteDestinationNetwork`, `RouteDestinationAssetId`) round-trip `ArkSwap.ProviderId` / `ArkSwap.Route` through the existing jsonb `Metadata` column until issue #79's dedicated columns land
- **ARK→BTC chain swap creation rework (PR #123)** — Fixed two stacked bugs that made every ARK→BTC cooperative refund silently no-op: (1) `ContractScript` was stored as the Ark address string (`vhtlcContract.GetArkAddress().ToString(...)`) instead of the hex `ScriptPubKey`, so `IClientTransport.GetVtxoByScriptsAsSnapshot` in `CoopRefundArkToBtcChainSwap` always returned empty and the refund returned `false` on every poll; (2) the VHTLC contract was never imported into `IContractStorage` on swap creation, so even with the correct script the `IContractStorage.GetContracts` lookup would fail. Both fixed by moving VHTLC construction into `BoltzSwapsService.CreateArkToBtcSwapAsync` (now takes an `OutputDescriptor` for the refund destination instead of a raw pubkey hex), calling `IContractService.ImportContract` in the new `RegisterArkToBtcChainSwapAsync` **before** any funds are committed, and saving the swap row with `contract.GetArkAddress().ScriptPubKey.ToHex()` as the `ContractScript`
- **PaymentTrackingService** — `IHostedService` (lifecycle: subscribe in `StartAsync`, unsubscribe in `StopAsync`) that auto-updates payment statuses from VTXO/intent/swap events; serialises `OnVtxoChanged` via `SemaphoreSlim` so concurrent VTXOs at the same payment request don't race read-compute-write on `ReceivedAmount`; accumulates per-asset amounts via `MergeAssets`
- **OutputDescriptor / SigningRepository** — Vendored NBitcoin.Scripting (parser combinators, descriptor model) in `NArk.Abstractions/Scripting/`
- **HdWalletRecoveryService** — Gap-limit scanner that rebuilds local contract state after HD wallet re-import by sweeping derivation indices and querying registered `IContractDiscoveryProvider`s (OR semantics). Ships indexer, boarding-UTXO, and Boltz-swap providers; custom sources plug in via DI.
- **IWalletRecoveryService / WalletRecoveryService / WalletRecoveryReport** — Wallet-type-agnostic recovery facade (PR #104) in `NArk.Swaps.Recovery`. `RecoverAsync(walletId, options?, ct)` dispatches by `WalletType`: **HD** → `HdWalletRecoveryService.ScanAsync` (gap-limit index scan across signers — including deprecated/legacy — restores boltz swaps in-line via the discovery providers); **SingleKey** → ensure the deterministic default contract exists (`EnsureSingleKeyContractAsync` derives one tagged `Source=recovery` if storage is empty), then `SwapsManagementService.RestoreSwaps` for its descriptor directly (no index to scan; throws if `AccountDescriptor` is null). Both paths then call `PendingArkTransactionRecoveryService.FinalizePendingArkTransactionsAsync(walletId)` to finalize stranded in-flight Arkade txs, poll the indexer via `VtxoSynchronizationService.PollScriptsForVtxos` for every recovered offchain (non-boarding) script, and call `SwapsManagementService.ScanRecoverableSwapsAsync` for the post-recovery swap-audit snapshot. Returns `WalletRecoveryReport(WalletType, HdScan?, ContractsRecovered, RestoredSwaps, SwapAudit, FinalizedPendingTxIds, FundsScriptsSynced)`; `ContractsRecovered` is the **delta** newly persisted by this run (not the total in storage). Lives in `NArk.Swaps` because it composes both Core recovery services and swap services; registered as a singleton by `AddArkSwapServices` (same call that already registered `BoltzSwapDiscoveryProvider`). Boarding UTXOs are reconciled by their own on-chain discovery path, not this indexer poll
- **RecoveryDelegateConfig** — Optional list of delegate (auto-renewal) public-key descriptors a wallet may have used (`NArk.Abstractions.Recovery`). When registered in DI, `IndexerVtxoDiscoveryProvider` additionally derives an `ArkDelegateContract` per delegate descriptor at each index — mirroring the canonical `arkade-os/ts-sdk` restore that derives both `DefaultVtxo` and `DelegateVtxo` scripts. Empty / not registered = no delegation probe (default)
- **IndexerVtxoDiscoveryProvider** — arkd-indexer probe upgraded (PR #104) to derive the full **cross-product** of candidate contracts per index: `{ current signer ∪ DeprecatedSigners } × { current exit delay ∪ mainnet-legacy 7-day exit delay (605184s, mainnet-only) }`, times `{ default ArkPaymentContract } ∪ { ArkDelegateContract per RecoveryDelegateConfig.Delegates entry }`. All candidate scriptPubKeys are probed in **one indexer query** via `GetVtxoByScriptsAsSnapshot` and the returned VTXOs map back to the exact owning contract by `scriptPubKey` hex; early-exit once every candidate has a hit. Closes the silent-zero-result gap on server-key rotation (funds locked under a previous server signer were missed by the prior single-`ArkPaymentContract`-against-current-signer probe) and the mainnet exit-delay shortening gap (arkd only advertises the CURRENT delay; the hardcoded `MAINNET_UNILATERAL_EXIT_DELAY` legacy fallback recovers VTXOs minted under the original 7-day delay). Reconstructs each deprecated signer's `tr(<x-only>)` descriptor via the new `KeyExtensions.ToOutputDescriptor(ECXOnlyPubKey, Network)` helper. **Server-info caching** rewritten to hold the result (with a `SemaphoreSlim` first-fetch lock) instead of a `Lazy<Task<ArkServerInfo>>`: a `Lazy` would permanently publish a *faulted* task if the first fetch failed mid-scan, poisoning every later probe into a silent empty result; the new shape lets a transient failure be retried on the next index and honors the cancellation token through the lock and the fetch
- **ArkApplicationBuilder** — Fluent builder for configuring all NArk services via IHostBuilder; `WithBlockchain<T>()` registers the unified `IBitcoinBlockchain` impl (replaces the prior `WithTimeProvider<T>()`)
- **ArkNetworkConfig** — Pre-configured per-network record (Mainnet / Mutinynet / Regtest) carrying `ArkUri`, `ArkadeWalletUri`, `BoltzUri`, `ExplorerUri`, plus nullable defaults `EsploraUri`, `ElectrumWsUri`, `ElectrumTcpUri` (`tcp://host:port`). Values mirror the canonical Arkade ts-sdk defaults so apps that need an `IBitcoinBlockchain` (Esplora flavor) can wire it without their own NBXplorer / bitcoind: `services.AddEsploraBlockchain(new Uri(ArkNetworkConfig.Mainnet.EsploraUri!))`. Electrum ports verified against public Fulcrum hosts (only `:50001` plain-TCP is exposed on Mainnet / Mutinynet; TLS goes via the WSS endpoint at `:443`); Regtest uses `:50000` (nigiri's electrs binary port; `:30000` on the same container is the HTTP REST endpoint, a different protocol). New fields are additive nullable defaults — existing named-args callers are untouched
- **IBitcoinBlockchain** — Unified blockchain interface (6 members: `GetChainTime`, `GetUtxosAsync`, `BroadcastAsync`, `BroadcastPackageAsync`, `GetTxStatusAsync`, `EstimateFeeRateAsync`). Collapses the previous split `IBoardingUtxoProvider` / `IChainTimeProvider` / `IOnchainBroadcaster` trio. Three concrete impls under `NArk.Core/Blockchain/`: `NBXplorerBlockchain`, `EsploraBlockchain`, `RpcBlockchain` (RPC throws `NotSupportedException` on `GetUtxosAsync` — no native address index). DI helpers `AddNBXplorerBlockchain` / `AddEsploraBlockchain` / `AddRpcBlockchain` register the right slot; last-registration-wins lets a custom impl override
- **UnilateralExitService** — Orchestrates the unilateral-exit state machine (`Broadcasting` → `AwaitingCsvDelay` → `Claimable` → `Claiming` → `Completed`). Stateful flow via `StartExitAsync(walletId, vtxoOutpoint, claimAddress)` + `ProgressExitsAsync()` (idempotent re-invocation, watchtower visibility, `MaxBroadcastRetries=10` cap). Also exposes a stateless one-shot API: `BroadcastExitChainAsync` returns an `ExitPlan` (wallet id, vtxo outpoint, claim address, leaf txid, CSV delay) the caller persists in whatever form they want; `ClaimMaturedExitAsync(ExitPlan)` returns the claim txid (or `null` if CSV hasn't matured). Wired via `AddUnilateralExit()`. CPFP via `BroadcastWithCpfpAsync` activates when an `IFeeWallet` is registered (gracefully falls back to direct broadcast otherwise). Skips on-chain `Commitment` rows in the broadcast loop
- **VirtualTxService** — Fetches and stores virtual tx branches from arkd via `GetVtxoChainAsync` + `GetVirtualTxsAsync`. Two modes via `VirtualTxOptions.DefaultMode`: **Lite** (default — stores txids + expiry only, defers hex fetch to `StartExitAsync`'s `EnsureHexPopulatedAsync`) and **Full** (stores raw tx hex at every VTXO arrival, two arkd round-trips per VTXO scaling with chain depth). Persists the **whole chain** (including the on-chain `Commitment` root, hex-null since arkd's `GetVirtualTxs` doesn't carry it) tagged with `ChainedTxType` (`Unspecified` / `Commitment` / `Ark` / `Tree` / `Checkpoint`). Upserts only overwrite the type when upgrading from `Unspecified` (preserves provenance). `ParseVirtualTx` branches on chained type: Tree txs lift `PSBT_IN_TAP_KEY_SIG` and assemble `WitScript([sig])` directly (PSBTs from arkd don't carry `witness_utxo` so `PSBT.Finalize()` doesn't work); Ark / Checkpoint try `Finalize+ExtractTransaction`, falling back to lifting `FinalScriptWitness` on `PSBTException`
- **ExitWatchtowerService** + **ExitWatchtowerBackgroundService** — Detect partial tree broadcasts and auto-start unilateral exits on owned VTXOs whose ancestors hit the chain (derives a boarding-contract claim address via `IContractService`). Skips VTXOs without stored branches before making RPC calls
- **VtxoChainAutoFetchService** — Opt-in hosted service (`AddVirtualTxAutoFetch()`) that listens to `IVtxoStorage.VtxosChanged` and queues a chain fetch for every new VTXO above the configured worth-threshold (`VirtualTxOptions.MinFetchAmount`). `HasBranchAsync` short-circuit makes duplicate events cheap. Replaces the batch-only `PostBatchVirtualTxFetchHandler` so VTXOs arriving from spend-change / payment / swap-claim / sweep paths also get their chains pre-stored
- **PostSpendVirtualTxPruneHandler** — Auto-wired prune-on-spend handler (serializable transaction to fix a concurrency race in `PruneForSpentVtxoAsync`). Safe regardless of whether auto-fetch is on
- **P2ACpfpBuilder** — Builds v3 CPFP children for 1p1c package relay of TRUC tree txs. Two-stage fee-rate adjustment (signs twice if vsize estimate was off). `IFeeWallet.SelectFeeUtxoAsync` returns `ICoin?` (NBitcoin standard, no parallel `FeeUtxo` type); signing is delegated via `IFeeWallet.SignFeeUtxoAsync(outpoint, sighash, sighashType)` — the SDK never holds raw key material, so hardware wallets / HSMs / remote signers / BTCPay's internal signer can plug in
- **IExitSessionStorage** / **IVirtualTxStorage** — Exit-pipeline persistence. Three storage options: EF Core (opt-in via `ConfigureArkExitEntities()` — adds `ExitSessionEntity` / `VirtualTxEntity` / `VtxoBranchEntity` to the model; per-tx model deduplicates shared tree nodes across sibling VTXOs), in-memory (`InMemoryExitSessionStorage` + `InMemoryVirtualTxStorage` backed by `ConcurrentDictionary`, wired via `AddInMemoryExitStorage()` — same code paths as EF, no schema), or no storage at all via the stateless `ExitPlan` API
- **ArkdVersion** — `NArk.Core/Transport/ArkdVersion.cs`. Injects version headers on every gRPC + REST request via `InjectHeader` (on the `HttpClient` default headers and the gRPC `Metadata`). `X-Build-Version` carries `TargetBuild` (the arkd build the SDK targets, `0.9.9`); `ThrowIfVersionRejected` raises `IncompatibleSdkVersionException` on a `BUILD_VERSION_TOO_OLD` error detail. **PR #139** adds `X-SDK-VERSION` — the SDK's own version as a `dotnet-sdk/{version}` product token (`SdkName = "dotnet-sdk"`) so arkd can distinguish the .NET SDK from sibling SDKs (e.g. ts-sdk) on the wire. `SdkVersion` is `ThisAssembly.AssemblyInformationalVersion` (Nerdbank.GitVersioning) with the SemVer `+commit` build-metadata suffix stripped by `StripBuildMetadata` (e.g. `1.0.327-beta`). Both headers are added idempotently. Pinned by `NArk.Tests/BuildVersionHeaderTests.cs`
- **AssetPacketBuilder** — Builds the OP_RETURN "asset packet" payload for Arkade asset transfers (`NArk.Core/Assets/`). `Build` emits `AssetGroup` entries in deterministic `(AssetId, GroupIndex)` ordinal-hex order — independent of input order or internal `HashSet` enumeration, and matching rust-sdk's `(txid, groupIndex)` sort. Guarantees byte-exact reproducibility across runs and cross-SDK fixture parity with ts-sdk / rust-sdk. Pinned by `NArk.Tests/AssetPacketBuilderTests.cs` (order-independence) and the fixture-driven suite under `NArk.Tests/Assets/` (ts-sdk-sourced `asset_ref` / `asset_input` / `asset_output` / `metadata` JSON, including `MetadataList` Merkle-hash vectors)
