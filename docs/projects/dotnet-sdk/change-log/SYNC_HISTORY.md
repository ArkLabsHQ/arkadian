**Highlights**:
- **Deterministic preimage scheme** — Reverse and chain swap preimages are now derived from the wallet's signing material so a restored wallet can re-derive them and claim outstanding VHTLCs. Scheme:
  ```
  message  = SHA-256( "Arkade-Boltz-Preimage-v1" || xonly_pubkey(32B) || u32_le(index) )
  sig      = BIP-340-Schnorr( descriptor_key, message, aux_rand=null )
  preimage = SHA-256( sig )
  ```
  Same `(wallet, pubkey, index)` → same signature → same preimage. The signed message bundles three things:
  - **Tag** (`"Arkade-Boltz-Preimage-v1"`) — domain-separates this signature from any other use of the key, versioned for future bumps, and intentionally protocol+provider scoped (`Arkade`+`Boltz`) rather than SDK-scoped so an Arkade wallet built on any sibling SDK (TypeScript, Go, Rust, .NET) produces the same preimage from the same wallet material and can recover swaps the .NET SDK created.
  - **X-only pubkey (32B)** — anchors on the canonical x-only public key, *not* the descriptor's string form. A signing descriptor (with key-origin + derivation path + checksum) and the bare receiver descriptor a restore reconstructs serialize differently for the same key, so anchoring on `.Extract().XOnlyPubKey.ToBytes()` keeps create-time and restore-time derivation byte-identical.
  - **`u32` LE index** — always `0` today; baked into v1 so multi-preimage-per-descriptor recovery iteration is forward-compatible without a scheme bump.
- **`SwapsManagementService`** — Two new methods drive the scheme: `internal static byte[] BuildPreimageMessage(OutputDescriptor descriptor, uint index)` (pure formatter — pinned by `PreimageDerivationTests`) and `private async Task<byte[]> DerivePreimageAsync(walletId, descriptor, index, ct)` (resolves the wallet's signer via `IWalletProvider.GetSignerAsync`, signs the SHA-256 message hash, returns `SHA256(sig.ToBytes())`). `InitiateReverseSwap`, `InitiateBtcToArkChainSwap`, and `InitiateArkToBtcChainSwap` now derive the preimage at `index: 0` before calling into `BoltzSwapsService`. Watch-only wallets (signer resolves to `null`) fall through to `RandomUtils.GetBytes(32)` — they don't get the recovery story, but they keep working.
