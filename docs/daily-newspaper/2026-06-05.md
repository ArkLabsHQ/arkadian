Anyone consuming the admin proto (telemetry, ark-faucet operator dashboards, kms-unlocker) will want to regenerate against the new `GetCollectedFees` RPC.

### Most important — expanded

1. **ts-sdk v0.4.33 + coinflip live → go-sdk Arkade gap is now load-bearing.** Yesterday ts-sdk released v0.4.33 with the full high-level Arkade contract API: `Arkade.connect()`, the `Program` model splitting named functions into a tapscript segment (on-chain) and an arkadeScript segment (emulated, bound by co-signer tweak), placeholder resolution for `$param`/`<SERVER_KEY>`/`<COSIGNER_KEY>`, a fluent builder, and `parseArtifact(json)` consuming compiler-style JSON artifacts. The same day, `coinflip.mutinynet.arkade.sh` went live on mutinynet running on this API — first production arkade-script covenant app. The parity report **escalated the gap severity to HIGH**: go-sdk and dotnet-sdk are now missing a user-facing API layer that has a deployed reference app. This matters to dusan because Arkade wallet's contract-execution path eventually runs through go-sdk; without a Go equivalent of `Arkade.connect()`/`Program`, every coinflip-class contract has to be either reimplemented as a custom go-sdk handler or proxied through ts-sdk. The 846-line `contract.ts` + 741-line test file is the spec for what a `gosdk/arkade` package would need to mirror.

2. **dotnet-sdk's preimage spec correction is a small but important cross-SDK update.** `a5f17d5` (`fix(swaps): derive preimage from the x-only pubkey, not descriptor.ToString()`) is critical because `descriptor.ToString()` was non-canonical — the HD signing descriptor and the bare receiver descriptor stringify differently for the same key, so a restore-time preimage would never match a create-time preimage. Fix: extract the 32-byte x-only pubkey and use it as the universal anchor. Scheme stays `v1` because it was never released. **Anyone implementing `Arkade-Boltz-Preimage-v1` in go-sdk (for fulmine swap recovery) must now use `xonly(32)`, not a descriptor string.** dotnet-sdk's tests pin the wire format and verify descriptor-form independence — good reference for go-sdk's implementation.

3. **arkd#1090 PostgreSQL must-fix before any go-sdk integration of `GetVirtualTxs` filters.** The bot review caught two real issues: (a) the down migration's view recreation happens before the `DROP COLUMN`, which PostgreSQL rejects due to dependency ordering, so rollback is broken; (b) when packet-type filters are applied without an accompanying time-range bound, the scan is silently truncated — wrong-data, not no-data, which is the worst failure mode. Until both are fixed, go-sdk wrapping `GetVirtualTxs` with filters would inherit the silent-truncation bug. Worth a comment on the PR.
