### Most important — expanded
1. **`Arkade-Boltz-Preimage-v1` cross-SDK protocol (dotnet-sdk, Andrew Camilleri / Kukks et al.).** Three commits on 2026-05-30 — `f00b948`, `d643a3b`, `a05f1fb`. The scheme derives the Boltz preimage as `SHA-256(signer.Sign(receiver_descriptor || index, SHA-256("Arkade-Boltz-Preimage-v1")))` with BIP-340 Schnorr (`aux_rand=null`) — deterministic per (key, message). The final rename commit explicitly says: _"NArk is .NET's internal shorthand … Renaming to 'Arkade-Boltz-Preimage-v1' lets any Arkade SDK (ts-sdk, go-sdk, rust-sdk, NArk) implement the same scheme byte-for-byte and recover swaps that another SDK created."_ This matters for you because cross-wallet VHTLC recovery is exactly the resilience story fulmine needs to tell, and go-sdk implementing this byte-for-byte is the lowest-friction way for a fulmine user to recover an outstanding swap created in another wallet.

2. **rust-sdk v0.9.1 → v0.9.2 TLS regression.** PR #233 (`100c53a`, `fix(grpc): set tls_config on manual endpoint connect`) — `ark_grpc::Client::connect()` was failing to set `tls_config` on manually-built endpoints, breaking all HTTPS ASP connections during the v0.9.1 window. Same-day patch in v0.9.2. The exposure window is the open question — any rust-sdk-based service that picked up v0.9.1 would have lost HTTPS ASP connectivity. Worth checking whether any internal services running rust-sdk were affected and whether go-sdk's gRPC client has analogous endpoint-builder paths that could regress similarly.

3. **Arkade extension system gap on go-sdk (ts-sdk v0.4.32, 2026-05-29).** ts-sdk now exposes `arkade.*` namespace, `ArkadeScript` codec (mirrors `@scure/btc-signer`), `ArkadeVtxoScript` (VtxoScript subclass for introspector-bound keys), `EmulatorPacket` codec, `RestEmulatorProvider`, and crucially `Recipient.extensions: { type, payload }[]` on `sendOffChain` (collects all per-recipient extension packets into a single OP_RETURN). This is the surface that lets a wallet emit Arkade-script-driven contracts. go-sdk has nothing; rust-sdk has the low-level opcodes (in `ark-script` crate) but no higher-level API; dotnet-sdk has nothing. If the arkade-wallet (PWA) is the primary distribution and ts-sdk is its SDK, go-sdk parity isn't blocking _wallet_, but it does block fulmine and any Go-based integration from emitting Arkade contracts.
