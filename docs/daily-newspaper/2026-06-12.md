## Protocol surface — arkd → go-sdk

One commit in the last 24h, and it's substantial:

- **Settings domain with DB persistence and admin CRUD API** — `3334279` (#939, Bob Smith)
  - New `AdminService.GetSettings` / `UpdateSettings` gRPC + REST (`GET`/`POST /v1/admin/settings`) with a 21-field `Settings` message and `update_fields` partial updates; new macaroon permissions. Touches `api-spec/protobuf/ark/v1/admin.proto`, generated admin client code, `internal/interface/grpc/handlers/adminservice.go`, `permissions.go`.
  - **Impact on go-sdk**: the generated admin client needs proto regeneration to expose the new RPCs; `ark.proto` (the main client surface) is unchanged.
  - **Behavior change**: round min/max participants, exit delays, VTXO tree expiry, amount limits, max tx weight, ban params are now admin-mutable at runtime without restart. `GetInfo` digest now comes from the app layer (`info.Digest`, `info_cache.go` removed) — digest values may differ even with identical config. **Impact on fulmine/go-sdk**: anything caching `GetInfo` values at startup (fulmine does, for exit delays and amount limits) should re-validate on `digest` change.
  - **pkg/ark-lib (additive, safe)**: new `ParseRelativeLocktime(uint32)` and `MinAllowedSequence = 512` in `locktime.go`.
  - **Breaking (ops only)**: settings env vars removed from `internal/config` — env seeds first boot only, DB is then source of truth.
