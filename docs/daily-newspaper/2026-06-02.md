### Most important — expanded

**1. ts-sdk #535 batch-signing fix — go-sdk audit is the top action item today.**

Pietro Grandi merged `02b18252` 21 hours ago: three independent silent-corruption risks in the batch checkpoint signing path. Specifically: (a) the `BatchSignableIdentity.signMultiple` contract used to silently *assume* implementors preserved the server's pre-existing `tapScriptSig` — a signer that dropped it stranded the tx in pending with no error; (b) the index-paired `signedCheckpointTxs` ↔ `userSignedCheckpoints` arrays had no length guard, so a count mismatch silently dropped the tail or produced cryptic `undefined` access on the send path; (c) `combineTapscriptSigs` was appending `undefined` for missing `tapScriptSig` entries, corrupting witnesses with no error. Arkana's parity report explicitly flagged all three SDKs (go, rust, dotnet) to audit their batch-signing code for the same class. **Why it matters for you:** you maintain the go-sdk equivalents of these paths. A one-afternoon grep + audit of `Settle()` / batch checkpoint construction in go-sdk is cheap insurance against a money-loss class of bug — and if go-sdk turns out to have any of these latent, you'd want the fix in before the next release after the 60-day drought.
