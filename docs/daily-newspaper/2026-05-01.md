## Protocol surface — arkd → go-sdk

Single arkd commit visible in today's sync — but it is the day's largest signal.

- **`9246f043` [client-lib] Update wallet interface (#1008)** (Pietralberto Mazza, co-author: you; committed 2026-04-29). Touches the entire wrap surface (`pkg/client-lib/*` — `service.go`, `init.go`, `send.go`, `unroll.go`, `batch_session.go`, `funding.go`, `wallet/singlekey/bitcoin_wallet.go` shrank by ~half, store layer, plus new `sign_opts.go` and `vtxos_opts.go`).
  - **Impact on go-sdk:** hard break. Wrappers must:
    1. Drop `InitWithWallet` / `InitArgs.WalletType` — switch to `NewArkClient(WithWallet(...))`.
    2. Update `GetAddresses` consumers for the new typed return — offchain/boarding/redemption are now `[]types.Address`, not `[]string`.
    3. Re-implement any custom `WalletService` against the new key-ref API (`NewKey`/`GetKey`/`ListKeys`/`NextIndex`) and the explorer-free `SignTransaction(ctx, tx, keys map[string]string)`.
    4. Thread the new variadic `opts ...SignOption` / `...UnrollOption` (or accept defaults) through `SignTransaction`, `RegisterIntent`, `DeleteIntent`, `FinalizePendingTxs`, `CompleteUnroll`, `OnboardAgainAllExpiredBoardings`, `WithdrawFromAllExpiredBoardings`.
    5. Decide whether to expose the new `WithKeys(map[string]string) SignOption` cross-family option for per-input key-id routing.
  - **Impact on fulmine:** if fulmine embeds a custom `WalletService` or calls `InitWithWallet`, expect compile breaks on the next arkd/go-sdk bump. Coordinate with the go-sdk update.

(For context: arkd's wider 7-day window also carries `8e005262` buf release pipeline fix, `9aab67fc` redis transactional Pop+Delete, `26e3e84f` projection DB wait before stream events, `626abf9f` configurable postgres pool, `a2d86c81` gRPC max receive size — all already on master, none new today.)
