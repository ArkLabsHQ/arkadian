### Most important — expanded

1. **The indexer `isSpent` fix and the cross-SDK alert in the parity report.** ts-sdk merged `4fb4e914` today after yesterday's #dev question. The fix makes the indexer's `virtualStatus.state` ternary distinguish "spent but pending finalization" from "not found" — without it, a VTXO that is spent but whose checkpoint tx hasn't finalized looks identical to a missing VTXO. The parity report explicitly flags that **go-sdk, rust-sdk, and dotnet-sdk all query the same indexer state and need to verify their `spent`-on-pending handling aligns** once ts-sdk releases. This matters for go-sdk's `Settle()` and pending-tx recovery paths — if go-sdk treats a spent-but-pending VTXO as missing, it can either drop a recoverable tx or, worse, re-attempt a spend that the network has already accepted. Audit go-sdk's `indexer.GetVtxos` callers this week.

2. **ts-sdk's same-day revert of the spent-VTXO recovery filter.** `5e2fbfe7` (`fix(wallet): exclude spent VTXOs from pending-tx recovery filters`) went in and was reverted (`af553007`) within hours, leaving a `DEFAULT_TIMELOCK` fallback PR (`4026a7f2`/`6cb82c8d`) in the same batch. Pietro is iterating on the right way to filter spent VTXOs from recovery without breaking the new mandatory `csvTimelock` semantics. **Don't port this filter to go-sdk yet** — let ts-sdk settle the design over the next day or two. Worth watching #dev for the resolution.

3. **The introspector `feat/cashu-nullifier-pool` branch yesterday.** Andrew Camilleri landed in-script NUT-12 r-blinded DLEQ verification, `hash_to_curve` (with a bounded counter loop K=4), an Indexed Merkle Tree with non-membership + insert + coupled-update, and a full Cashu claim script — all running inside arkade script. Also a real engine fix: `5deaa1d` `OP_CAT must not append into aliased stack buffers`. The OP_CAT fix is the load-bearing item for dusan: any go-sdk contract handler that builds witnesses via concatenation is exposed to the aliasing bug until v0.0.3. The Cashu in-script work is a preview of where the engine + contract surface is going — Arkade Script as a real proof-verification environment.
