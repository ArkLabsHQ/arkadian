## Protocol surface — arkd → go-sdk

`master` advanced by **one commit** in 24h, and it lands directly on go-sdk's wrap surface.

- `2999d666` **client-lib: Add WithReceiver option & Update explorer and wallet interfaces (#1058)** — _Pietralberto Mazza (altafan)_
  - **Files** (20 files, +618/-293):
    - `pkg/client-lib/explorer/mempool/explorer.go` (+87/-, throttling), `explorer/service.go`
    - `pkg/client-lib/wallet/wallet.go`, `singlekey/wallet.go`, `singlekey/bitcoin_wallet.go`, `wallet_test.go`
    - `pkg/client-lib/{batch_session,funding,send,unroll,asset}.go` reworked to consume the new option
    - new `pkg/client-lib/receiver_opts.go` (+115) and `receiver_opts_test.go` (+134)
  - **Breaking — Explorer**: `Explorer.GetUtxos(addr string)` → `GetUtxos(addresses []string)`. Multi-address batched lookup with throttling.
    - **Impact on go-sdk**: every go-sdk caller of `GetUtxos` (and any sibling/test that builds against `pkg/client-lib/explorer`) needs to wrap its single address in a slice and adapt to batched return shape.
  - **Breaking — Wallet**: `WalletService.NextIndex(ctx)` removed; replaced by `NextKeyId(ctx, id) (string, error)` and `GetKeyIndex(ctx, id) (uint32, error)`.
    - **Impact on go-sdk**: any custom `WalletService` impl in go-sdk (or downstream like fulmine) must implement the two new methods. The single-key wallet already in tree was updated in this PR, so the upstream reference is in place — but external impls won't compile.
  - **New API — `WithReceiver(addr)`**: cross-family option satisfying `SendOption + BatchSessionOption + UnrollOption`; overrides change/destination address across `Send*`, `Settle`, `CollaborativeExit`, `Unroll`, `OnboardAgainAllExpiredBoardings`. Helpers: `validateOffchainAddress`, `validateOnchainAddress`, `validateOffchainOrOnchainAddress`.
    - **Impact on go-sdk**: additive — opens up explicit change-address override via `WithReceiver(addr)`.
    - **Privacy footgun**: per the changelog summary, `WithReceiver` **skips `wallet.NewKey`**, so reused change addresses are not recorded in the wallet. For fulmine accounting, that means a wallet using `WithReceiver` with a static address will not see those VTXOs through the normal "my keys" lookup path. Worth a sanity check before fulmine adopts it.

### Most important — expanded

1. **arkd #1058 is the work item this week.** What was a feature branch yesterday is now master. The `Explorer.GetUtxos` shape change (string → []string with throttling) and the `WalletService` rewrite (`NextIndex` → `NextKeyId(id) + GetKeyIndex(id)`) are both compile-time breaks for any go-sdk that vendors `pkg/client-lib/`. The `WithReceiver` addition is additive but carries a non-obvious privacy property — it bypasses `wallet.NewKey`, so a reused override address won't show up in the wallet's "my keys" set. **Action**: open the go-sdk bump PR (renames + slice-wrap) and decide explicitly whether fulmine should ever pass `WithReceiver` for an address it didn't derive — if yes, the wallet's accounting layer needs a parallel "external receivers" register.

2. **Lightspark Grid is now the strategic frame for arkade-wallet.** Marcus shipped a Visa-backed, dollar-denominated, AI-agent-friendly payments API on top of Bitcoin (Spark + Lightning). For a wallet team building a self-custodial Ark stack, this is the loudest "what does the user actually need" signal of the year: institutional rails are crystallising around Spark, not Ark, and they're aimed at app-developer distribution. It doesn't change today's PR list, but it's the right context for the next Arkade product-direction conversation — particularly whether arkade-wallet's value prop centres on self-custodial _BTC_ (where Ark's moat is real) vs. self-custodial _USD_ (where Lightspark Grid + Spark USDB now have a head-start with regulated distribution).

3. **VTXO persistence #480 is closing the script-correctness gap on ts-sdk first; go-sdk needs to track.** Tier 1 (2026-05-06, gate persisted VTXOs by owning script) and Tier 2 (today, script-scoped repository methods across all backends) both shipped on ts-sdk. The defect class — VTXOs persisted/served without their owning-script identity — is the kind of correctness bug that's painful in a multi-script wallet (HTLC + boarding + delegate + cooperative exit). go-sdk's storage layer should be audited for the same class while the ts-sdk diff is fresh, and Tier 3 (when it lands) likely tells us what's still missing.
