### Most important — expanded

1. **arkd signer-rotation + Boltz VHTLC recovery PR (open, awaiting review)** — opened 2026-06-10. This PR adds arkd-side support for migrating off deprecated signers AND a Boltz VHTLC recovery path; arkana classified it as PROTOCOL-CRITICAL because rotating signers changes every existing VTXO's spending conditions and exit-path validity. The VHTLC recovery half is the half that matters for *your* work: fulmine's VHTLC flow goes through this same Boltz swap settlement path, so whatever recovery semantics this PR settles on, fulmine will need to consume them. Worth reading the PR diff before it merges to know whether you'll need a fulmine-side update.

2. **VTXO intent TX_TOO_LARGE — empirical cap is 91, default is 50, discussion unresolved (#dev, 2026-06-05)** — @U07ML5C69RC tested locally and found the server rejects anything over 91 VTXOs in a single intent. go-sdk currently caps at 50. The team is split: hardcoded count cap vs. while-loop retry vs. weight-based estimation (which is more correct but more work). The fix shipped (50-cap is now everywhere), but the underlying design question is still open. Since go-sdk owns the canonical cap, any new approach lands in your repo first — be ready for a follow-up PR.

3. **LNURL-pay LUD-06 rejection on live lnurl-server (issue opened 2026-06-08)** — lnurl-server is generating LNURL-pay invoices where the invoice amount = requested amount + Boltz reverse-swap fee. LUD-06 (the LNURL-pay spec) requires exact match, so Phoenix/Mutiny/Zeus all reject. This is on the live production Boltz reverse-swap path, which means actual Arkade users trying to receive Lightning via LNURL are getting silently rejected by their LN wallet. Bug is logged but unfixed. If fulmine ever generates LNURL-pay invoices through the same path, same bug applies — worth verifying.
