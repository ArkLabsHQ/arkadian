### Most important — expanded

1. **rust-sdk's offchain-tx API promotion is a parity signal for go-sdk.** Lucas Soriano del Pino landed three back-to-back PRs in 24h — `Do not put submit_offchain_tx behind feature flag` (7292c42), `Make finalize_offchain_tx public` (d3adc0b), and `restore finalize pending offchain tx API` (af1490a). go-sdk (dusan's repo) wraps the same logical surface; if rust-sdk decided these belong in the supported public API, go-sdk should audit whether its equivalents are exposed the same way. This is the kind of cross-SDK shape change that creates silent drift unless caught early.

2. **dotnet-sdk #116 — deterministic Boltz preimages via BIP-340 sign-and-hash** (Andrew Camilleri, merged 12h ago). This is the recoverable-preimages scheme that @U0854KRKV3Q was asking @U07MSPULJLA about in #dev on 2026-06-04. The idea: derive swap preimages deterministically from a BIP-340 signature so they can be recovered after wallet restore. Fulmine handles Boltz submarine + reverse swaps directly — adopting this pattern would close a real recovery-UX gap and align fulmine with dotnet's approach before ts/go diverge further.

3. **ts-sdk's btcd Taproot tree fix is protocol-adjacent and needs verification, not just a version bump.** `fix(script): build Taproot script tree with btcd's algorithm` (8d432a13, Andrew Camilleri) changes how the script tree is constructed. Slack-monitor flagged that a discrepancy with btcd's canonical algorithm "could produce different script hashes affecting VTXO spend paths" and explicitly called out backward-compatibility verification as an action item. If go-sdk constructs the same script tree using its own pathway, dusan should diff the algorithm against btcd and against the ts-sdk fix to confirm parity before any existing-VTXO migration could be broken.
