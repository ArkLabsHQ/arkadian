### Most important — expanded

**1. dotnet-sdk #80 — Boltz 404 safety-net pattern (kukks, 269b877)**
What: When the configured Boltz endpoint changes (operator switches default URL), in-flight swaps created against the old instance return HTTP 404 indefinitely. dotnet-sdk now throws a typed `BoltzSwapNotFoundException` only on the specific 404+body match, and `SwapsManagementService.PollSwapState` tracks a per-swap consecutive-unknown counter; after 10 (~10 minutes at 1-min cadence) the swap is marked `Failed` with `Metadata["unknownToProvider"] = "true"` so consumer UIs can surface a "refund manually after CSV expiry" hint.
Who: Andrew Camilleri (kukks), merged today (2026-05-03 18:29 +0200).
Why for Dusan: go-sdk's Boltz integration has the same forever-Pending failure mode — and the symptom is exactly what the wallet team would hit if/when the default Boltz endpoint changes. The pattern (typed 404 detection, bounded retry counter, metadata hint) is small and portable. Mirroring it in go-sdk's swap polling closes a parity gap **and** unblocks fulmine + arkade-wallet from a class of stuck-Pending bugs.
