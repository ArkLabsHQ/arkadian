### Most important — expanded

1. **Arkade extension system parity gap is now real (and big).** The ts-sdk v0.4.32 release today gives every ts-sdk caller a public `arkade.*` API surface for emulator/introspector co-signed VTXOs, including a `Recipient.extensions` channel on `sendOffChain` that emits OP_RETURN Extensions. Dusan's go-sdk has none of the stack — not even low-level Arkade Script opcode helpers (rust-sdk at least has those in `ark-script`). This isn't a polishing gap; it's the difference between go-sdk callers being able to build emulator-mediated contracts and not. The arkade-wallet PWA stack will eventually want this, and right now only ts-sdk can serve it.

2. **MuSig2 nonce leak in dotnet-sdk #107 → #113 is a class warning, not just an incident.** Andrew Camilleri shipped watch-only + remote-signing as a new `WalletType` and the secret nonce was being passed across `IRemoteSignerTransport`; reuse of a MuSig2 private nonce allows private key derivation. The same-day fix (#113) puts the nonce inside the signer and never lets it cross the transport boundary. Worth dusan grepping go-sdk for any remote-signing or external signer interface and confirming the same containment rule holds — if go-sdk ever grows a remote-signing seam, this pattern is the reference.

3. **HTLC claimer is supposed to move into fulmine, and nothing has happened yet.** On 2026-05-26 @U07MSN1PNTU proposed in #dev: move HTLC claim code from bancod into fulmine as a standalone `htlc-claimer`/`covenant-claimer` binary, since "only Boltz uses it." @U07ML5CM486 (OpenIntentsFramework) agreed in principle. Five days on, no fulmine PR, and the bancod → solver rename has shipped — so the HTLC claimer is now stranded in a repo (`arkade-os/solver`) that's expanding past the scope it used to have. Worth either picking up the migration or pinging back to confirm someone owns it.
