### Most important — expanded

**1. boltz-swap: deferred ARK chain refunds are lost across restart (CRITICAL, OPEN).**
arkana flagged on 2026-05-25 that deferred refunds on the ARK chain are not persisted across boltz-swap service restarts — affected users with pending refunds will simply lose them on the next process restart. This is fulmine-adjacent in the most direct way: fulmine wraps boltz-swap to do submarine and reverse swaps, and any operational rollout (deploy, crash, reboot) of fulmine that triggers a restart of the underlying boltz-swap component would silently drop in-flight refunds. Until a fix lands, an operational rule of thumb: do not restart fulmine while a refund is pending without a manual drain step.

**2. ts-sdk defaults provider URLs to mainnet (#516, MERGED 2026-05-25).**
gringokiwi shipped four commits (`d682eac5` merge, plus `c87bc3da`, `cdeb6bb8`, `5d7eded9`) that move the network default to mainnet across address construction, on-chain address derivation, and provider URLs, and deprecate passing URLs as bare strings. The wallet PWA already ships this via #631. Anything downstream that previously relied on undefined-network → testnet-or-regtest behaviour will now silently land on mainnet. For arkade-wallet PWA: verify the bootstrap path explicitly sets network when running on staging/regtest — otherwise local dev builds will resolve to mainnet endpoints.

**3. Bitcoin Core 31.0 has been live on mainnet since 2026-04-19.**
arkana's research-monitor corrected itself on 2026-05-25: cluster mempool (PR #34616), V3 policy, sibling-eviction RBF, and improved RBF semantics are all already deployed in production on mainnet — prior research entries placing them in "rc4 / late 2026" were wrong. This matters for fulmine and arkd because forfeit and connector transactions live inside V3 / TRUC topologies. CPFP fee bumping behavior, package-RBF eligibility, and cluster-eviction rules are operationally different from pre-31.0 semantics. If you have any production assumptions baked from earlier Core releases (e.g. expected eviction order under fee pressure), they're worth re-verifying against the live policy.
