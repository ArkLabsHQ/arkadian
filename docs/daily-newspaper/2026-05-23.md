### Most important — expanded

1. **The "Split client-lib and client-wallet" PR is the single biggest item to watch for go-sdk.** arkana's slack-monitor flagged it 2026-05-21 as a "significant architectural split." `go-sdk/pkg/client-lib` is the thing go-sdk wraps; splitting it into `client-lib` (protocol) and `client-wallet` (wallet-side) will force go-sdk to either follow the split or bridge both. If it lands soon it lands during a 10-day go-sdk freeze (no commits since 2026-05-13), so the catch-up will be on you when you next push.

2. **ts-sdk 0.4.28 ships `Wallet.restore()` gap-scan — go-sdk has no equivalent.** kukks landed a 30-commit feature branch (#492) that adds explicit gap-limit recovery via `Wallet.restore()`, `ContractManager.scanContracts`, `Discoverable` capability, and `discoverAt` on both default and delegate contract handlers. This is exactly the kind of feature that the parity-desk would flag (last parity report is stale at 2026-04-03, hence skipped) — go-sdk doesn't have a public restore/discovery API on its HD wallet today. If Chimera or any third party adopts go-sdk before this is matched, they'll notice.

3. **arkd `WithTxOutsTaprootTree` is small but exactly the kind of additive client-lib change that creates silent drift.** louisinger added a new SendOption letting callers attach a taproot tree to send outputs. go-sdk wraps `pkg/client-lib/send.go` — without a parity wrapper, go-sdk users have to drop down to client-lib to use it, which defeats the SDK abstraction. One PR's worth of work to expose it; the longer it waits, the more SendOptions accumulate.
