### Gaps where go-sdk lags
- **HDDescriptorProvider / Phase C1** — ts-sdk v0.4.24 ships full `HDDescriptorProvider` (`peekNextIndex`, `consumeNextIndex`, `rotateReceive`, mutex-serialised); no equivalent in go-sdk, rust-sdk, or dotnet-sdk. Gap **deepens** vs. ts-sdk daily.
- **HD wallet gap-limit recovery** — ts-sdk ✅, rust-sdk ✅, dotnet-sdk ✅ (PR #77 merged 2026-04-29). go-sdk **still ❌**.
- **`DescriptorProvider` interface / descriptor-based signing** — ts-sdk only.
- **Multi-timelock VTXO discovery** (`walletContractTimelocks`) — ts-sdk only; without it, go-sdk users miss VTXOs sent under the legacy 605184s exit delay after an ASP parameter change.
- **`ContractWatcher`** — go-sdk PR #153 still not merged to master (per 2026-04-24 entry); `contract/` directory absent from `origin/master` tree. Until merged, go-sdk has no contract-scoped VTXO tracking.
- **`ElectrumOnchainProvider`** — ts-sdk only (since v0.4.20). go-sdk uses mempool.space; rust-sdk uses BDK+Esplora; dotnet-sdk uses arkd transport.
- **Forfeit/unilateral exit key separation** — rust-sdk only (commit `2caa25d`, 2026-05-04). Other SDKs assume forfeit key == unilateral exit key.
- **Bigint asset amounts** — ts-sdk v0.4.23 went `bigint`; go-sdk still `int64`. Cross-SDK wire-level coordination required (parity report 2026-05-05).
